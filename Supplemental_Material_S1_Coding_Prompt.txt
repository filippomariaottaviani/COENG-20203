Supplemental Material S1
Coding prompt for the contextual A-B-C coding

Manuscript: Mapping Methods and Applications in Construction Project Management Analytics
Journal of Construction Engineering and Management, manuscript COENG-20203

GPT-6 (OpenAI), in its Pro setting through the ChatGPT interface, received the prompt
below once, in a new conversation, together with a file of the 780 included records
(PAPER_KEY, TITLE, ABSTRACT). The coding it returned is used exactly as returned
(see Contextual Coding of Applied Links in the manuscript). The message under
"RESUME MESSAGE" was to be sent, unchanged, only if the model stopped before the
last abstract; it was not needed, because the model completed all 780 abstracts without stopping.

================================================================================
PROMPT
================================================================================
TASK
You will receive included abstracts from a systematic review of construction project management analytics. For each abstract, identify every paper-specific A–B–C pathway that the abstract reports: a method (A), applied to a performance domain (B), for a management purpose (C). Report how many pathways each abstract contains, and give the pathways.

A pathway is accepted only when the abstract describes the actual application, implementation, testing, or evaluation of the named method or practice, in that study, for that purpose and domain. Do not accept methods that are only mentioned, only proposed, planned, recommended, or assumed to be useful. Do not accept a pathway that depends on general knowledge rather than on what the abstract reports.

INPUT AND INDEPENDENCE
The attached file has three columns: PAPER_KEY, TITLE, ABSTRACT. Read each abstract on its own. Use only the title and abstract text and the instructions in this message. Do not use outside knowledge about the paper, its authors, or its journal. Do not open, search, or use any other file, earlier conversation, memory, or workspace document, and do not compare your results with any other coding.

BATCHES (run all of them without waiting for me)
Process all 780 abstracts in 16 consecutive batches of 50, in file order: 1–50, 51–100, 101–150, ..., 701–750, 751–780.
- Before starting each batch, re-read the EVIDENCE TIER and OUT-OF-TAXONOMY sections of this message and apply them exactly as written. Apply the same rules in every batch; do not change how you apply any rule as the work proceeds, and do not adjust later batches to resemble earlier ones.
- When a batch is finished, save it as a downloadable file named coding_<first>_<last>.json (for example coding_001_050.json), then start the next batch immediately. Do not stop, summarize, or ask me whether to continue between batches.
- After batch 751–780, write coding_001_780_all.json, containing all 780 records in input order, and give me download links for all 17 files. Then report, for each batch: abstracts, accepted pathways, DIRECT, CONTEXTUAL, uncertain, proposed, and out-of-taxonomy entries.
- If you must stop before abstract 780 because of a length or time limit, first save every completed batch as a file, then end your reply with exactly this line: STOPPED AFTER ABSTRACT <number>. Never leave a batch half-saved.

If a method is not in this list, assign its family from its description and set "family_from_crosswalk": false.

EVIDENCE TIER (apply literally)
- "DIRECT": a single sentence of the abstract names the method and states both the domain and the purpose. Give exactly one quote: that sentence.
- "CONTEXTUAL": no single sentence does this, and the link needs two or three adjacent sentences. Give those two or three sentences as separate quotes.
- Never give more than one quote for a DIRECT pathway, and never fewer than two for a CONTEXTUAL pathway.

WHAT TO RECORD FOR EACH ACCEPTED PATHWAY
- "A", "B", "C": the exact labels above, with the numeric indices.
- "tier": as defined above.
- "method_names": the method or methods as named in the abstract.
- "applied_action": one sentence in English stating what the study did with the method for this purpose and domain.
- "evidence_quotes": passages copied exactly, character for character, from the abstract (no paraphrase, no added punctuation, no changed capitalization). Each quote must be a substring of the abstract.
- "confidence": a number from 0 to 1 for how clearly the abstract supports the pathway.
- "family_from_crosswalk": true or false, as above.

WHAT TO RECORD SEPARATELY (not counted)
- "uncertain": a candidate you could not decide, with the reason.
- "proposed": a use the authors propose, plan, or recommend but do not carry out. Give the A/B/C labels and the quote.
- Do not place these in "accepted".

OUT-OF-TAXONOMY TERMS
If the abstract applies a method, performance domain, or management purpose that does not fit any label above, do not force it into a label and do not count it as accepted. Record it in "out_of_taxonomy":
- "slot": "A", "B", or "C", the dimension the term would occupy.
- "term": the term as written in the abstract, copied exactly.
- "evidence_quote": a verbatim quote from the abstract.
- "closest_label": the nearest existing label, or "none".
- "reason": one sentence on why no label fits.
Record only terms that the abstract applies, in the same way as an accepted pathway. Do not record terms that are only background, proposed, or mentioned.

OUTPUT
Return one JSON object per abstract, in input order, with exactly these keys:
{
  "PAPER_KEY": "...",
  "accepted_count": 0,
  "accepted": [
    {"A": "...", "A_index": 0, "B": "...", "B_index": 0, "C": "...", "C_index": 0,
     "tier": "DIRECT|CONTEXTUAL", "confidence": 0.0, "family_from_crosswalk": true,
     "method_names": ["..."], "applied_action": "...", "evidence_quotes": ["..."]}
  ],
  "uncertain": [{"A": "...", "B": "...", "C": "...", "reason": "...", "evidence_quote": "..."}],
  "proposed": [{"A": "...", "B": "...", "C": "...", "evidence_quote": "..."}],
  "out_of_taxonomy": [{"slot": "A|B|C", "term": "...", "evidence_quote": "...", "closest_label": "...", "reason": "..."}]
}
If an abstract has no accepted pathway, return "accepted_count": 0 and an empty "accepted" list, and give a short "zero_reason" (for example, "methods mentioned only as background" or "no method named").
Return only the JSON array in the file, with no commentary inside it.

Process the abstracts exactly as given. Do not skip, merge, or reorder them. Do not count the same pathway twice within an abstract.

Start now with abstracts 1–50 and continue through abstract 780.
